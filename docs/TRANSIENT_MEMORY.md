# Transient memory planning

Logical resource descriptions do not prescribe heap offsets. The runtime must query actual allocation size/alignment and supply plain `MemoryRequirement` values. Heap class distinguishes buffers, RT/DS textures and other textures, so the plan works with D3D12 Resource Heap Tier 1 restrictions. A compatibility key allows additional device/backend restrictions. Dedicated requests receive separate heaps and never reuse slots.

The allocator sorts active transients by first use and ResourceId. It chooses the smallest fitting reusable slot, breaking ties by slot creation order. A slot is eligible only when its previous lifetime ends strictly before the new first use, heap class/key match, its capacity fits the requested bytes and its offset satisfies the new alignment. Otherwise it appends an aligned slot in the first matching heap. Slots do not split, and the algorithm does not claim optimal packing.

Offset addition, size rounding, heap padding and total-byte addition are checked against unsigned overflow. Actual resource extents remain recorded separately from slot capacity. Heap sizes round to their maximum required alignment. `committed_bytes` is the sum of individually rounded requirements; `physical_bytes` is the sum of planned heap sizes. Positive savings and padding overhead are separate nonnegative fields, so alignment overhead cannot wrap into fictional savings. Runtime records actual created heap sizes independently before claiming a memory result.

Reference mode disables reuse while retaining placed resources and the same pass semantics. Imports and culled-only resources never enter the arena. Exported transients remain live through graph completion. Each frame context owns a separate physical arena, and its fence must complete before that arena is recorded again.

Each reused slot exposes an exact predecessor/successor chain. Every placed resource receives an activation barrier, including reference-mode resources that do not reuse memory. The native barrier deliberately uses null `pResourceBefore` for every activation, while the plan retains the exact predecessor as diagnostic provenance. This conservative scope covers the slot's last occupant from a previous frame and avoids cross-format Depth/Color metadata ambiguity observed on hardware with a named before-resource. Reference mode reports activation barriers but zero reuse events. Aliasing never preserves contents; RT/DS callbacks clear the full attachment after activation. The planner returns transients to Common at their last retained lifetime position before a different occupant activates.

Core supports generic power-of-two alignment, as exercised by 1/8-byte CPU fixtures. Native D3D12 heap alignment is a separate restriction: the v0.1 backend must request default 64-KiB placement alignment (no small-resource alignment or MSAA), check the device requirement, and create matching 64-KiB-aligned heaps. It must not pass arbitrary CPU fixture alignment to `CreateHeap`.

The independent property oracle checks byte intersections for every pair of simultaneously live allocations at every pass position, rather than trusting slot IDs. It also checks actual extents, heap bounds, alignment, dedicated isolation, metrics, and exact alias-chain coverage.

The D3D12 executor queries every active transient with `GetResourceAllocationInfo`, feeds those plain values to Core, creates class-appropriate `ID3D12Heap` objects, verifies their returned descriptions, and calls `CreatePlacedResource` at the planned offsets. It creates one arena per frame context. Reports expose planned bytes, per-arena returned heap bytes, all-frame total and placed-resource call count; these are resource heap reservations, not a claim about residency or total driver memory.
